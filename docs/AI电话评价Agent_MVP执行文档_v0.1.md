## 1. 执行依据与边界

本执行文档只实现主 PRD 已确认的 MVP 内容，需求来源为：

- `OPEN-P0-02`：最小知识 schema
- `OPEN-P0-03`：证据与信息磨损契约
- `OPEN-P0-04`：人工 Gate 与审批责任
- `OPEN-P0-05`：变更提案与发布门槛
- `OPEN-P0-07`：Prompt 编译契约
- `OPEN-P0-08`：发布包自描述与人工交付
- `OPEN-P0-09`：描述性知识与规范性政策边界
- `OPEN-P0-10`：证据型变更
- `OPEN-P0-11`：最小权限与敏感数据治理
- `OPEN-P0-12`：独立平台前端工作台、显示内容与控制契约
- `OPEN-P1-09`：已确认的首版视觉参考基线

产品是独立网页工作台，和 Mentor/EvalLab 平行；不实现下游真实电话评分运行、不接入 Mentor API、不复制 EvalLab 的业务字段和运行结构。原有 `mvp_v1.py` 不作为正式实现依据。

## 2. MVP 交付物

1. 可运行的独立 HTML 工作台：六类入口、任务详情骨架、状态/参数/证据/知识 diff/Prompt/日志窗口。
2. 最小后端服务：任务、来源快照、证据、知识对象、变更提案、Gate、编译草稿、发布包和审计记录的持久化接口。
3. 标准 TXT 导入与解析流程：原始快照不可变，解析结果可重跑并保留版本。
4. 发布包导出与人工交付核验卡：包含 manifest、Prompt、契约、哈希、回归状态和 delivery record。
5. 结构化验收数据和最小测试集，覆盖正常、证据不足、冲突、阻断、审批和哈希不一致场景。

## 3. 前端实现基线

### 3.1 信息架构

左侧导航固定为：工作台、知识更新任务、证据与知识、变更与版本、Prompt 与发布包、审计与设置。

### 3.2 页面骨架

任务详情页采用：上下文栏 + 主工作区 + 右侧控制/详情栏 + 底部事件流。

### 3.3 必须显示

- 任务：`task_id`、状态、`session_id`、来源 ID/文件哈希、目标专家、当前 Gate。
- 证据：`evidence_id`、source/utterance/span、说话人、时间戳、`evidence_kind`、上下文 refs、来源哈希。
- 知识：对象 ID、类型、版本、状态、作用域、父版本、证据 refs、冲突集。
- 变更：`change_id`、变更类型、旧/新对象、基线、差异、影响范围、Gate、阻断原因。
- 编译：组版本、政策版本、编译器/配置版本、Prompt 大小、输入哈希、Prompt/manifest 哈希。
- 交付：发布包 ID/版本、适用范围、方式、接收方、`integrity_verified/sent_unverified`、delivery ID。

### 3.4 控制口

任务导入/重解析/暂停恢复；证据归类/绑定/补访；知识变更提案与 G3/G4 审核；选择批准版本并编译、查看 diff、提交 G5；导出发布包、复制核验卡、记录交付和哈希核验；查看审计及非语义显示设置。

禁止提供直接修改已批准对象或正式 Prompt 的输入框；语义设置不得由普通前端设置静默覆盖。

## 4. 后端与数据实现顺序

1. 建立不可变来源快照与 TXT 解析结果：`source`、`session`、`utterance`、`evidence`。
2. 建立知识对象最小 schema：稳定 ID、状态、版本、作用域、父版本、证据 refs、冲突集和 linkage。
3. 建立变更提案与 Gate 状态机：候选→待确认→已批准/已拒绝/仅存档；G1/G2/G3/G4/G5 记录责任人、决定、理由、时间、证据和审计 ID。
4. 建立 approved-only Prompt 编译器：生成 manifest、Prompt 哈希和编译结果；候选、冲突未决和未批准对象不得进入正式 Prompt。
5. 建立发布包、核验卡、delivery record 和 `access_audit`。
6. 接入前端各窗口和控制口，所有操作返回结构化状态、对象 ID/版本及审计 ID。

## 5. 权限与敏感数据

沿用 D1/D2/D3 三层：发布包 D1 可交付；知识/证据/审核记录 D2 受任务范围控制；原始 TXT、实名、候选人/JD 和完整上下文 D3 默认脱敏且禁止导出。D3 查看、下载、脱敏、交付和归档均写入不可变 `access_audit`。

## 6. 验收标准

- 能从标准 TXT 创建任务并保留原始快照和来源哈希。
- 每个可发布知识对象都能回链到原始 TXT 的 source/utterance/span。
- 候选、冲突未决、未批准对象不会进入正式 Prompt。
- G3/G4/G5 缺失责任人或审核记录时，编译/发布被阻断。
- Prompt 与 manifest 可重复生成，哈希可核验；哈希不一致时交付标记异常。
- 前端能展示全部必显参数、Gate、阻断原因、事件日志和审计 ID。
- D3 敏感内容默认脱敏，越权访问、导出或哈希不匹配均被记录并阻断。
- 三张视觉参考图可被界面实现 agent 在本地直接读取。

## 7. 分步实施与回写

实施顺序：数据模型与来源快照 → 解析/证据 → 知识与变更 → Gate/权限 → Prompt 编译 → 发布包 → 前端工作台 → 集成验收。

每一步发现的新需求必须先回写主 PRD，再更新本执行文档；不得在实现中静默扩展范围。完成每一步后记录测试结果、真实 case 问题和对应 PRD 归因。

## 8. 可执行任务清单（每项约 15–30 分钟）

### 阶段 A｜准备与骨架

- [ ] **A-01｜读取基线与视觉资产（15 分钟）**
  - 输入：主 PRD v0.35、本执行文档、`assets/ui-reference/*.png`。
  - 动作：确认需求 ID、边界、六类入口、必显字段、禁止项；逐张查看三张参考图。
  - 产出：`implementation-notes.md`，列出实现范围和明确不做事项。
  - 验证：记录 PRD 版本和三张图路径；不得开始编码前端业务逻辑。

- [ ] **A-02｜建立项目目录和启动方式（20 分钟）**
  - 动作：建立前端、后端、数据、测试、静态资源目录；确定本地启动命令和端口。
  - 产出：最小可启动空壳，README 写明启动方式。
  - 验证：空壳可启动、首页可访问；不引入 Mentor/EvalLab 接口。

- [ ] **A-03｜建立前端布局骨架（25 分钟）**
  - 动作：实现深色底色、左侧分组导航、中央工作区、右侧详情/控制栏、底部事件流。
  - 产出：六类入口可点击切换的静态页面骨架。
  - 验证：布局与参考图的信息密度和层级一致；状态同时显示文字和颜色。

### 阶段 B｜来源、解析与证据

- [ ] **B-01｜定义来源与任务数据结构（25 分钟）**
  - 动作：实现 `task`、`source`、`session`、`utterance` 的最小字段和稳定 ID。
  - 产出：schema/迁移文件及一条示例数据。
  - 验证：保存原始文件哈希；重复导入不覆盖旧快照。

- [ ] **B-02｜实现标准 TXT 导入（25 分钟）**
  - 动作：读取会议头、说话人、时间戳和正文；保留原文快照。
  - 产出：导入接口/命令和解析结果。
  - 验证：使用 `全文.txt`、`case C01.txt` 或 `caseC02.txt` 完成一次导入；失败要返回结构化错误。

- [ ] **B-03｜实现证据定位与回链（25 分钟）**
  - 动作：建立 `evidence_id`、source/utterance/span、上下文 refs、evidence_kind 和来源哈希。
  - 产出：证据查询接口及前端证据卡。
  - 验证：任一证据可定位回原始 TXT；字符偏移仅用于展示，规范定位使用字节偏移。

- [ ] **B-04｜实现证据不足/冲突展示（20 分钟）**
  - 动作：支持 `insufficient_evidence`、`conflict_set`、反例/矛盾/明确否定标记。
  - 产出：证据状态标签和冲突详情。
  - 验证：冲突并存，不静默覆盖；证据不足不自动补写结论。

### 阶段 C｜知识对象与变更

- [ ] **C-01｜实现最小知识 schema（30 分钟）**
  - 动作：实现对象类型、稳定 ID、状态、版本、父版本、ownership/applicability scope、linkage。
  - 产出：知识对象表/接口和示例 Graph、Fragment、Overlay。
  - 验证：已批准对象不可原地修改；结构身份变化生成新 ID 并保留 supersedes。

- [ ] **C-02｜实现候选知识与基线 diff（25 分钟）**
  - 动作：将证据抽取结果保存为候选对象，支持与已批准基线比较。
  - 产出：知识列表、diff 卡和影响范围摘要。
  - 验证：候选对象不进入正式 Prompt；diff 能回链证据。

- [ ] **C-03｜实现变更提案（25 分钟）**
  - 动作：支持 add/modify/reclassify/link/attach 及结构变更类型；记录 change_id、原因、证据、基线。
  - 产出：变更提案接口和变更详情页。
  - 验证：没有证据回链或基线的结构变更被阻断。

### 阶段 D｜Gate、权限与审计

- [ ] **D-01｜实现 G1/G2/G3/G4/G5 状态机（30 分钟）**
  - 动作：实现 Gate 状态、角色、决定、理由、时间、证据 refs、前后对象和审计 ID。
  - 产出：Gate 操作接口和审核面板。
  - 验证：缺责任人或审核记录时阻断后续阶段；G4 政策责任例外可审计。

- [ ] **D-02｜实现 D1/D2/D3 权限边界（25 分钟）**
  - 动作：实现角色 + 任务范围 + 数据级别的最小访问判断；D3 默认脱敏和禁止导出。
  - 产出：权限中间件/策略函数和越权测试。
  - 验证：越权查看、下载、导出被拒绝并写入 `access_audit`。

- [ ] **D-03｜实现不可变审计事件（20 分钟）**
  - 动作：记录访问、脱敏、导出、审核、交付、哈希不匹配、归档事件。
  - 产出：审计查询页和事件结构。
  - 验证：审计事件不可静默删除或覆盖，含 actor、scope、对象、时间和结果。

### 阶段 E｜Prompt、发布包与交付

- [ ] **E-01｜实现 approved-only 编译输入（25 分钟）**
  - 动作：按适用范围→Guard/政策→策略→话术→评分顺序收集已批准对象。
  - 产出：编译输入清单和阻断报告。
  - 验证：候选、冲突未决、未批准、跨组对象不能进入正式编译。

- [ ] **E-02｜实现 Prompt/manifest 可复现编译（30 分钟）**
  - 动作：生成只读 Prompt、manifest、输入对象哈希、编译器/配置版本和 SHA-256。
  - 产出：编译草稿页和编译产物。
  - 验证：相同输入可复现相同输出；超预算阻断，不静默截断或压缩。

- [ ] **E-03｜实现发布包与核验卡（25 分钟）**
  - 动作：打包 manifest、Prompt、输入/输出契约、变更/回归摘要和核验卡。
  - 产出：发布包下载/预览页。
  - 验证：发布包不含原始访谈、候选人/JD 或完整 D3 内容。

- [ ] **E-04｜实现人工交付记录（20 分钟）**
  - 动作：记录 delivery_id、包版本、方式、接收方、Prompt 哈希、核验状态和备注。
  - 产出：交付记录页。
  - 验证：核验成功标记 `integrity_verified`；无反馈只能标记 `sent_unverified`。

### 阶段 F｜前端窗口与控制口

- [ ] **F-01｜实现工作台总览（25 分钟）**
  - 动作：展示待处理任务、Gate、最近变更、发布状态、异常提醒。
  - 产出：工作台首页。
  - 验证：所有卡片可跳转到对应任务/对象/审计记录。

- [ ] **F-02｜实现任务与来源/证据窗口（30 分钟）**
  - 动作：实现导入、解析状态、原文只读、证据高亮、定位和脱敏提示。
  - 产出：知识更新任务页和证据页。
  - 验证：支持重新解析但不覆盖原快照；D3 未授权不展开。

- [ ] **F-03｜实现知识/变更版本窗口（30 分钟）**
  - 动作：实现对象列表、结构 diff、话术 diff、冲突、Gate 控制。
  - 产出：证据与知识页、变更与版本页。
  - 验证：批准/驳回/存档后状态和版本可追溯。

- [ ] **F-04｜实现 Prompt/发布/审计窗口（30 分钟）**
  - 动作：实现只读 Prompt、manifest、哈希、发布包导出、交付记录、审计查询。
  - 产出：Prompt 与发布包页、审计与设置页。
  - 验证：禁止手改正式 Prompt；每个控制口显示结构化结果和审计 ID。

### 阶段 G｜集成验收与回写

- [ ] **G-01｜跑通最小闭环（30 分钟）**
  - 动作：TXT 导入→证据→候选知识→G3/G4→新版本→编译→G5→发布包→交付记录。
  - 产出：一条可复现演示任务及截图/日志。
  - 验证：全链路状态、对象 ID、版本和审计 ID 连续可追踪。

- [ ] **G-02｜执行异常与安全验收（25 分钟）**
  - 动作：测试重复导入、解析失败、证据不足、冲突、缺 Gate、超预算、哈希不匹配、越权访问。
  - 产出：异常测试记录和阻断结果。
  - 验证：所有异常都阻断或降级为明确状态，不静默通过。

- [ ] **G-03｜回写执行文档与 PRD 归因（20 分钟）**
  - 动作：勾选已完成任务，填写产出/验证/问题；将新需求按 12.2 归因回 PRD。
  - 产出：更新后的执行文档、progress.md 和必要的 PRD patch。
  - 验证：执行文档当前执行位置与实际代码/页面一致。
