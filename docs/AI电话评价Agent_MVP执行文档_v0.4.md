## 1. 执行依据与边界

本执行文档只实现主 PRD 已确认的 MVP 内容，需求来源为：

- `OPEN-P0-02`：最小知识 schema
- `OPEN-P0-03`：证据与信息磨损契约
- `OPEN-P0-04`：人工 Gate 与审批责任
- `OPEN-P0-05`：变更提案与发布门槛
- `OPEN-P0-07`：Prompt 编译契约
- `OPEN-P0-08`：发布包自描述与人工交付
- `OPEN-P0-09`：描述性知识与规范性政策边界
- `OPEN-P0-10`：证据型变更
- `OPEN-P0-11`：最小权限与敏感数据治理
- `OPEN-P0-12`：独立平台前端工作台、显示内容与控制契约
- `OPEN-P1-09`：已确认的首版视觉参考基线
- `OPEN-P0-13`：LLM 配置与辅助提炼模块

产品是独立网页工作台，和 Mentor/EvalLab 平行；不实现下游真实电话评分运行、不接入 Mentor API、不复制 EvalLab 的业务字段和运行结构。原有 `mvp_v1.py` 不作为正式实现依据。

本执行文档的 A–I 阶段最初依据 PRD v0.36/v0.37 建立；J–P 在不改写历史完成事实的前提下，依次落地 PRD v0.38–v0.46 的目标专家归属、干净重跑、精确基线增量 Graph、节点原话版本、边条件校准、同源执行/评价 Prompt、导入基线编辑/复用及电话流程布局。产品在证据提炼、策略结构提炼、话术映射、Prompt 生成和可选布局分析环节借助可配置 LLM，但所有知识类 LLM 产出均为候选，不自动批准。当前运行快照为公司 OpenAI 兼容接口与 `gpt-5.6`；早期阶段中的 GLM-5.2 文字是当时真实验证记录，不作为当前默认配置。

## 2. MVP 交付物

1. 可运行的独立 HTML 工作台：工作台、任务与专家、Graph 审查、Prompt 与发布、审计与设置；逐条证据审核转为后台工程，相关证据在 Graph 详情中按需呈现。
2. 最小后端服务：任务、来源快照、证据、知识对象、变更提案、Gate、编译草稿、发布包和审计记录的持久化接口。
3. 标准 TXT 导入与解析流程：原始快照不可变，解析结果可重跑并保留版本。
4. Graph 中心审核与复用：完整基线+增量物化、节点多原话选择/校准、边条件校准、继承基线候选式编辑、独立电话流程布局和规范 Graph JSON 导出/再导入。
5. 同源执行/评价发布包与人工交付核验卡：包含电话执行、策略评价、话术评价、综合评价、权威路由表、manifest、契约、哈希、回归状态和 delivery record。
6. 结构化验收数据和最小测试集，覆盖正常、证据不足、冲突、阻断、审批、隔离、哈希不一致、稀疏导入和布局不影响知识等场景。

## 3. 前端实现基线

### 3.1 信息架构

左侧默认导航为：工作台、任务与专家、Graph 审查、Prompt 与发布、审计与设置。逐条证据审核不作为默认页面；证据分类在后台进行，与结构/话术变化直接相关的原文、说话人和时间位置在 Graph 详情中复核。

### 3.2 页面骨架

任务详情页采用：上下文栏 + 主工作区 + 右侧控制/详情栏 + 底部事件流。

### 3.3 必须显示

- 任务：`task_id`、状态、`session_id`、来源 ID/文件哈希、目标专家、当前 Gate。
- 证据：`evidence_id`、source/utterance/span、说话人、时间戳、`evidence_kind`、上下文 refs、来源哈希。
- 知识：对象 ID、类型、版本、状态、作用域、父版本、证据 refs、冲突集。
- 变更：`change_id`、变更类型、旧/新对象、基线、差异、影响范围、Gate、阻断原因。
- 编译：组版本、政策版本、编译器/配置版本、Prompt 大小、输入哈希、Prompt/manifest 哈希。
- 交付：发布包 ID/版本、适用范围、方式、接收方、`integrity_verified/sent_unverified`、delivery ID。

### 3.4 控制口

任务导入/显式干净重跑/重解析/暂停恢复；目标专家和精确基线选择；整份访谈增量学习；同一画布查看候选完整图/现有基线/增量 diff 并整图批准或驳回；选择批准版本并编译、提交 G4/G5；导出发布包、复制核验卡、记录交付和哈希核验；查看审计及非语义显示设置。

禁止提供直接修改已批准对象或正式 Prompt 的输入框；语义设置不得由普通前端设置静默覆盖。

## 4. 后端与数据实现顺序

1. 建立不可变来源快照与 TXT 解析结果：`source`、`session`、`utterance`、`evidence`。
2. 建立知识对象最小 schema：稳定 ID、状态、版本、作用域、父版本、证据 refs、冲突集和 linkage。
3. 建立变更提案与 Gate 状态机：候选→待确认→已批准/已拒绝/仅存档；G1/G2/G3/G4/G5 记录责任人、决定、理由、时间、证据和审计 ID。
4. 建立 approved-only Prompt 编译器：生成 manifest、Prompt 哈希和编译结果；候选、冲突未决和未批准对象不得进入正式 Prompt。
5. 建立发布包、核验卡、delivery record 和 `access_audit`。
6. 接入前端各窗口和控制口，所有操作返回结构化状态、对象 ID/版本及审计 ID。

## 5. 权限与敏感数据

沿用 D1/D2/D3 三层：发布包 D1 可交付；知识/证据/审核记录 D2 受任务范围控制；原始 TXT、实名、候选人/JD 和完整上下文 D3 默认脱敏且禁止导出。D3 查看、下载、脱敏、交付和归档均写入不可变 `access_audit`。

## 6. 验收标准

- 能从标准 TXT 创建任务并保留原始快照和来源哈希。
- 每个可发布知识对象都能回链到原始 TXT 的 source/utterance/span。
- 候选、冲突未决、未批准对象不会进入正式 Prompt。
- G3/G4/G5 缺失责任人或审核记录时，编译/发布被阻断。
- Prompt 与 manifest 可重复生成，哈希可核验；哈希不一致时交付标记异常。
- 前端能展示全部必显参数、Gate、阻断原因、事件日志和审计 ID。
- D3 敏感内容默认脱敏，越权访问、导出或哈希不匹配均被记录并阻断。
- 三张视觉参考图可被界面实现 agent 在本地直接读取。

## 7. 分步实施与回写

实施顺序：数据模型与来源快照 → 解析/证据 → 知识与变更 → LLM 配置 → Gate/权限 → LLM 辅助提炼 → LLM 生成评价 Prompt → 发布包 → 前端工作台 → 集成验收 → 方向纠正与 C/D/E 重基线。

每一步发现的新需求必须先回写主 PRD，再更新本执行文档；不得在实现中静默扩展范围。完成每一步后记录测试结果、真实 case 问题和对应 PRD 归因。

### 阶段 I｜Graph 可视化、既有 Graph 导入与结构对照（I-01～I-06 已完成）

本阶段记录 G/H 实际试用后发现的可理解性问题，先冻结执行方向，不立即改 PRD、不把讨论内容当作已完成实现。目标是让审核者能看懂候选 Graph 自身的结构，也能判断它相对于既有策略 Graph 的位置、增删和变化，而不是只看节点/边数量及对象 ID。

#### I 阶段已冻结的产品与工程判断

1. **Graph 是结构化审核对象，不是 ID 列表。** 页面必须可视化节点、边、触发/停止条件和分支标签；点击任一对象后，侧栏展示证据原文、证据 ID、话术映射、候选状态、重复/疑似重复信息和审核操作。
2. **候选图、既有基线图、差异图分开呈现。** 有既有 Graph 时显示基线与候选的叠加/对照；没有既有 Graph 时至少显示候选图自身的自动布局结构。基线未被本轮访谈覆盖的节点不能直接标记为“删除”，应标记为“本轮未覆盖”。
3. **渲染与布局拆分。** 当前前端是原生 HTML/CSS/JavaScript，优先评估 `Cytoscape.js + cytoscape-elk` 作为交互渲染与自动布局组合；`XYFlow/React Flow` 作为未来 React 化方案，不在本轮直接引入；`Mermaid` 仅作为静态预览或导出格式，不作为主要审核画布。
4. **既有 Graph 先作为 baseline/reference。** 导入的手工 Graph 没有系统化 `evidence_refs`、Gate 审计和知识版本时，不能直接变成 approved 知识或进入 Prompt；需经人工映射证据并通过 G3 后才可进入正式知识链路。
5. **`.drawio` 是一等导入格式，不要求转 CSV。** CSV 只能表达简单的 source/target 边表，会丢失布局、节点类型、边标签、页面和视觉语义。系统内部统一转换为版本化 JSON，供候选 Graph、基线 Graph、差异和测试使用。
6. **不做静默语义合并。** 自动匹配只提供“可能对应/未匹配”提示；节点名称、边条件或话术变化必须保留差异并由人工确认。一次访谈只覆盖局部策略时，缺少的基线内容不能被当作删除。

本地样例已验证导入可行：`流程图kiki.drawio` 可解析出 29 个节点、36 条边和 20 个边标签；`流程图looper.drawio` 可解析出 34 个节点、45 条边和 24 个边标签。两份文件当前为标准未压缩 `mxfile → diagram → mxGraphModel → root → mxCell` XML；后续解析器需兼容 draw.io 的压缩页面格式。
