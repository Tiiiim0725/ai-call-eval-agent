## 核心问题
1. 哪些文件属于第二位猎头的结构化策略文档，哪些属于完整交流记录？
2. 资料明确支持哪些节点、候选人状态、动作、分支条件、结束路径和通话后动作？
3. 不同资料之间是否存在命名、顺序、分支或话术归属冲突？
4. 哪些内容只能标记为信息缺口或 AI 推断，不能写入正式规则？

## 已作决定
| 决定 | 理由 |
|---|---|
| 当前只产出待确认节点表、待确认边表、信息缺口与冲突 | 用户要求确认前不生成最终评估 Prompt |
| 证据优先级为确认图 > 结构化策略文档 > 完整交流记录 > AI 推断 | 遵循项目交接规则 |
| AI 推断不进入正式规则 | 防止把外部经验或常识误写成真人策略 |
| 策略错误与话术错误分开评价 | 防止同一错误重复扣分 |
| `C01.txt`、`C02.txt` 不作为第二位猎头证据 | 说话方明确标为 AI 猎头，且核心表达可追溯到 Kiki 的交流记录 |

## 阶段 F 协作契约
- PRD 是产品需求唯一真源；目标、北极星指标、功能、数据源、架构、信息流/数据流、产品运作、验收与评价均需在 PRD 中有出处。
- 未敲定内容使用“待讨论/假设/候选方案”状态，不写成已批准需求。
- 每次讨论形成明确增改结论后，同步更新 PRD 的正文、决策记录、版本号和变更日志。
- 执行文档只允许引用已批准 PRD 中的需求 ID；不得补入 PRD 未收录的功能或工程范围。
- 若执行阶段发现新增需求，先退回修改并批准 PRD，再更新执行文档。
- 当前目录不是 Git 仓库；版本治理暂以文档内版本、决策状态和变更日志为准。
